# link-skill-packer

**Git이나 플러그인 마켓플레이스를 쓸 수 없을 때, 스킬을 검사해 복사용 ZIP 파일로 묶습니다.**

> 이 스킬의 핵심은 압축이 아니라 검사입니다. 검사를 통과하고 포장할 대상을 확인하기 전에는 ZIP을
> 만들지 않습니다. 스킬을 대신 고치거나 완성된 ZIP을 외부로 전송하지도 않습니다.

마켓플레이스를 등록한 뒤 **터미널**에서 설치합니다.

```bash
claude plugin install link-skill-packer@link-skills
```

Python이 필요하며 표준 라이브러리만 사용합니다.

| 호출 | 결과 | 하지 않는 일 |
|---|---|---|
| `link-skill-packer:link-skill-packer` | 검사된 `<스킬이름>-skill.zip`과 `INSTALL.md` | 스킬 수정, 일부 파일만 선택, 외부 전송 |

---

## 언제 쓰나

- 회사에서 GitHub나 플러그인 마켓플레이스가 차단돼 있을 때
- 직접 만든 스킬을 공유 드라이브·메일·메신저로 넘겨야 할 때
- 다른 컴퓨터에 복사한 스킬이 오류 없이 목록에서 사라졌을 때

받는 사람은 스킬을 설치하기 위해 패커를 따로 받을 필요가 없습니다. ZIP 안의 `INSTALL.md`를 읽고
스킬 폴더를 복사하면 됩니다. 패커는 복사 뒤 문제가 생겼을 때 원인을 진단하는 용도로도 쓸 수 있지만,
그 컴퓨터에서 실행할 수 있는 패커가 이미 있을 때의 선택 사항입니다.

스킬이 목록에는 있지만 엉뚱한 요청에서 발동한다면 패커의 범위가 아닙니다. 발동 조건을 검토하는
[`link-skill-authoring`](../link-skill-authoring/README.md)을 사용하세요.

---

## 목록에 뜨지 않는 세 가지 흔한 원인

| 원인 | 확인 방법 |
|---|---|
| `SKILL.md` 맨 앞의 인코딩 표식이나 설정 영역이 깨짐 | `check`가 찾음 |
| 설치한 세션에서 바로 확인함 | 스킬 목록은 세션 시작 때 읽으므로 새 세션에서 확인 |
| 폴더를 한 단계 깊게 복사함 | `<skills-dir>/<이름>/SKILL.md` 구조인지 확인 |

압축을 풀 때 ZIP 이름을 딴 바깥 폴더까지 복사하면 다음처럼 한 단계 깊어집니다.

```text
잘못된 구조
<skills-dir>/고객관리-skill/고객관리/SKILL.md

올바른 구조
<skills-dir>/고객관리/SKILL.md
```

진단만 요청받았다면 `check` 결과와 폴더 위치를 확인해 원인을 알려 주고 멈춥니다. ZIP을 만들어 달라는
요청이 없었으므로 포장까지 이어서 진행하지 않습니다.

## 검사 결과 읽기

검사 결과는 `FAIL`, `WARN`, `NOTE` 세 단계입니다.

### FAIL — 고친 뒤 다시 검사

받는 컴퓨터에서 스킬이 발동하지 않을 것으로 파일만 보고 확정할 수 있는 문제입니다. 하나라도 있으면
ZIP을 만들지 않습니다.

| 검사 항목 | 발생하는 문제 |
|---|---|
| `SKILL.md`가 없음 | 스킬 폴더가 아님 |
| 문서 맨 앞에 BOM이 있음 | 문서 맨 앞의 YAML 설정 영역인 frontmatter를 읽지 못할 수 있음 |
| frontmatter 블록이 없음 | 발동에 필요한 메타데이터가 없음 |
| `description`이 없음 | 모델이 언제 스킬을 불러야 할지 판단할 설명문이 없음 |
| 따옴표 없는 `description`에 `:` 뒤 공백이 있음 | YAML이 문장을 다른 구조로 해석해 설정을 읽지 못함 |

패커는 이 문제를 대신 수정하지 않습니다. 보내는 과정에서 파일을 고치면 작성자가 시험한 스킬과
받는 사람이 받은 스킬이 달라지기 때문입니다.

### WARN — 작성자가 판단

정상인 예와 위험한 예를 기계가 구분할 수 없어 포장 전에 확인해야 하는 항목입니다. ZIP 생성을
막지는 않지만, 대상 확인 질문과 함께 보여 줍니다.

| 검사 항목 | 판단이 필요한 이유 |
|---|---|
| 절대경로·UNC 경로·홈 디렉터리 | 문서 예시라면 괜찮지만 실제 의존 경로라면 다른 컴퓨터에서 깨짐 |
| 스킬 폴더 밖을 가리키는 링크 | 설명문 속 예시일 수도 있고 ZIP에 빠지는 실제 파일일 수도 있음 |
| 비밀번호처럼 보이는 문자열·사설 IP·이메일 주소 | 자리표시자일 수도 있고 외부로 나가면 안 되는 실제 정보일 수도 있음 |
| 한 문서에서 일부 경로만 풀림 | 사용자 프로젝트 경로일 수도 있지만 번들 파일의 오타일 수도 있음 |
| 들어 있는 Python 파일이 파싱되지 않음 | 실행 실패 가능성이 있고 외부 패키지 목록도 완전하게 만들 수 없음 |
| 스킬치고 큰 묶음 | 샘플 데이터나 빌드 결과가 실수로 들어갔을 수 있음 |

패커는 “절대경로 발견”처럼 판정을 끝내 버리지 않고, 어느 파일의 무엇이 왜 애매한지 보여 줍니다.

### NOTE — 답을 요구하지 않는 참고 정보

포장 여부를 바꾸지는 않지만 받는 사람에게 유용한 정보입니다.

| 참고 항목 | 처리 |
|---|---|
| 함께 담기는 실행 스크립트 | `INSTALL.md`에 실행기를 기록 |
| 외부 의존성 | ZIP에 담을 수 없으므로 이름을 기록 |
| frontmatter의 `name`과 폴더 이름이 다름 | ZIP과 호출 이름은 폴더 이름을 그대로 사용 |
| 한 문서의 참조 경로가 모두 풀리지 않음 | 사용자 프로젝트를 설명하는 문서로 보고 참고만 남김 |

Python 파일은 import를 읽어 표준 라이브러리가 아닌 패키지 이름을 기록합니다. JavaScript 파일은
Node.js가 필요하다는 점까지만 알 수 있고 npm 패키지는 분석하지 않습니다. `INSTALL.md`에도 이
한계를 밝힙니다.

## 포장 순서

### 1. 검사하고 대상 확인

스킬 폴더를 찾아 `check`를 실행합니다. `FAIL`이 있으면 문제를 알려 주고 멈춥니다. 통과했다면 파일
수와 크기, `WARN` 항목, 평범하지 않은 파일을 대상 이름과 함께 보여 주고 한 번 확인합니다.

```text
`고객관리`를 포장합니다 — 파일 12개, 84 KB.
`실적_2026Q2.xlsx`는 스킬 자료보다 업무 데이터에 가깝습니다.
이 폴더를 그대로 포장할까요?
```

파일 전체를 무조건 나열하지는 않습니다. 평범한 파일은 폴더별 개수만 보여 주고, 다음과 같이 포장
여부를 바꿀 수 있는 파일만 이유를 붙입니다.

- `.xlsx`, `.csv`, `.zip`, `.pdf` 같은 데이터 파일
- 초안·임시·사본처럼 읽히는 이름
- 스킬치고 큰 파일
- `references/` 안에 있지만 다른 문서가 연결하지 않는 마크다운

전체 파일 목록이 필요하면 `--all`을 사용합니다.

### 2. 확인받은 뒤 ZIP 생성

확인받으면 `build`를 실행합니다. `build`도 같은 검사를 다시 실행하므로, 검사를 건너뛰고 ZIP만 만들
수는 없습니다.

제외할 파일이 있다면 원본 폴더에서 옮기거나 지운 뒤 처음부터 다시 검사해야 합니다. 제외 옵션으로
일부만 골라 담지는 않습니다. 일부만 담으면 작성자가 시험한 스킬과 전달된 스킬이 서로 달라지기
때문입니다.

## 만들어지는 ZIP

```text
<스킬이름>-skill.zip
├── INSTALL.md          설치 방법, 요구 사항, 파일 목록과 검증값
└── <스킬이름>/          이 폴더를 스킬 경로에 그대로 복사
```

`INSTALL.md`에는 다음 정보가 들어갑니다.

- Python·PowerShell·bash·Node.js 같은 필요한 실행기
- Python 스크립트에서 확인한 외부 패키지
- 담긴 파일 목록과 파일별 SHA-256 검증값
- 설치 위치와 확인 방법
- 새 세션에서 확인해야 한다는 안내
- 바깥 폴더가 아니라 안쪽 스킬 폴더를 복사하라는 안내
- 파일을 텍스트로 다시 만들지 말고 원본 그대로 복사하라는 안내

SHA-256은 파일이 전달 중 바뀌었는지 확인하기 위한 값입니다. 일부 편집기나 복사 방식으로
`SKILL.md`를 다시 생성하면 BOM이 붙거나 내용이 달라질 수 있으므로, 파일 내용을 읽어 새로 쓰지 말고
그대로 복사합니다.

받는 사람의 에이전트에게 명령을 실행시키는 지시는 `INSTALL.md`에 넣지 않습니다. 설치에 필요한
정보와 사람이 확인할 복사 절차만 담습니다.

---

## 하지 않는 것

- 스킬을 만들거나 고치지 않습니다.
- 스킬의 내용이나 발동 조건이 좋은지 평가하지 않습니다.
- 폴더에서 일부 파일만 골라 담지 않습니다.
- 패키지나 실행기를 자동으로 설치하지 않습니다.
- ZIP을 메일·메신저·공유 드라이브로 전송하지 않습니다.

패커가 보장하는 것은 **스킬이 잘 만들어졌다는 것**이 아니라 **옮기는 과정에서 확인 가능한 문제로
깨지지 않았다는 것**입니다.
