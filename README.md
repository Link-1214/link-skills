# link-skills

**AI가 조사하고 비교하고 검증하되, 결정권은 사람이 갖도록 만든 에이전트 스킬 모음입니다.**

AI와 일하다가 "이건 다음에도 같은 절차로 처리하는 편이 낫겠다"고 느낀 작업을 스킬로 만들어
모았습니다. 각 스킬은 객관적으로 확인할 수 있는 사실은 스스로 판단하고, 대상·범위·약속·디자인
방향처럼 결과를 바꾸는 결정 앞에서 멈춰 묻습니다.

Claude Code에서는 플러그인으로 설치할 수 있습니다. 다른 에이전트에서는 저장소를 내려받고
`SKILL.md`를 직접 읽히면 됩니다. 필요한 기능과 제약은 [다른 에이전트에서 사용](#다른-에이전트에서-사용)에
정리했습니다.

---

## 어떤 스킬을 쓰면 되나

플러그인 3개에 스킬 4개가 들어 있습니다.

| 필요한 일 | 호출 | 결과 | 하지 않는 일 |
|---|---|---|---|
| 시각 방향을 고른다 | `link-design-pitch:link-design-pitch` | 29개 카탈로그에서 고른 시안 10개와 `DECISION.md` | 방향을 대신 결정하거나 실제 화면을 구현하지 않음 |
| 정한 방향을 실제 내용에 맞춰 구체화한다 | `link-design-pitch:link-design-pitch-detail` | 실제 화면별 상세 시안, 디자인 토큰, 적용 작업 목록 | 소스 코드나 Word·Excel·PowerPoint 파일을 직접 수정하지 않음 |
| 스킬의 품질과 책임 범위를 정한다 | `link-skill-authoring:link-skill-authoring` | 발동 조건·추측 처리·계약 경계에 대한 기준과 검토 결과 | 스킬 작성·테스트 절차를 대신하지 않음 |
| Git이나 마켓플레이스 없이 스킬을 넘긴다 | `link-skill-packer:link-skill-packer` | 검사된 ZIP 파일과 설치 안내 | 스킬을 고치거나 ZIP을 외부로 전송하지 않음 |

### 디자인 스킬의 순서

두 디자인 스킬 사이에는 실제 기능과 내용을 만드는 단계가 있습니다.

```text
질문 5개 → 시안 10개 → 추천 → 사용자가 방향 선택
                                  ↓
                   실제 기능과 내용을 별도로 제작
                                  ↓
          실제 화면별 상세 시안·적용 명세 → 인터랙션 선택
```

두 번째 스킬은 실제 화면을 고치는 구현 스킬이 아닙니다. 만들어진 화면이나 문서를 기준으로 디자인을
구체화하고, 구현에 필요한 수정 위치와 순서를 기록합니다.

## 빠른 시작 — Claude Code

먼저 **터미널**에서 마켓플레이스를 등록하고 전체 플러그인을 설치합니다.

```bash
claude plugin marketplace add Link-1214/link-skills
claude plugin install link@link-skills
```

그다음 **Claude Code 대화창**에서 플러그인을 다시 불러옵니다.

```text
/reload-plugins
```

이제 이름으로 스킬을 부를 수 있습니다.

```text
link-design-pitch 실행해 줘. 새 대시보드의 시각 방향을 정하고 싶어.
```

상황이 맞으면 Claude가 자동으로 스킬을 고를 수도 있습니다. 비슷한 디자인 스킬이 여러 개 설치돼
있다면 어느 스킬이 선택될지 보장되지 않으므로, 확실히 쓰고 싶을 때는 이름을 지정하세요.

## 플러그인이 처음이라면

| 용어 | 이 저장소에서 뜻하는 것 |
|---|---|
| **마켓플레이스** | 플러그인 목록을 제공하는 저장소. 한 번 등록합니다 |
| **플러그인** | 설치 단위. 스킬 하나 이상을 담습니다 |
| **스킬** | 실제 작업 절차. 대화에서 이름으로 호출합니다 |

설치는 플러그인 단위입니다. 한 플러그인 안의 스킬은 따로 설치할 수 없습니다. 함께 써야 의미가 있는
스킬은 하나의 플러그인으로 묶었습니다.

## 스킬별 요약

### link-design-pitch

**디자인 용어를 몰라도 시각 방향을 눈으로 비교해 고르게 합니다.**

1. 대상, 산출물, 핵심 색, 레이아웃, 유도할 행동을 한 번에 묻습니다.
2. 29개 방향이 담긴 카탈로그에서 현재 작업에 맞는 10개를 고릅니다.
3. 열 방향을 실제 제목·수치·항목으로 렌더합니다.
4. 장단점을 비교하고 하나를 추천한 뒤, 사용자가 고를 때까지 멈춥니다.

웹·데스크톱·모바일 앱과 발표 자료·스프레드시트·문서·인쇄물의 방향을 잡는 데 쓸 수 있습니다.
브라우저가 아닌 산출물의 시안은 실제 화면을 그대로 캡처한 것이 아니라 HTML로 만든 근사치입니다.

선택이 끝나면 다음 파일이 남습니다.

| 파일 | 내용 |
|---|---|
| `01-directions.html` · `.png` | 실제 내용으로 만든 시안 10개 |
| `DECISION.md` | 질문의 답, 비교 결과, 추천과 선택, 디자인 토큰 |

[사용법 자세히](plugins/link-design-pitch/README.md)

### link-design-pitch-detail

**선택한 방향을 이미 만들어진 실제 내용에 맞춰 상세 시안과 구현 목록으로 구체화합니다.**

`DECISION.md`에 선택한 방향이 기록돼 있고 실제 기능이나 내용이 만들어진 뒤에 사용합니다. 서로 다른
실제로 다른 화면을 빠짐없이 상세 시안에 담고, 강조 순서와 글자 대비를 측정하며, 코드 프로젝트라면
수정할 파일과 줄을 찾습니다.

실제 코드나 문서 파일을 직접 수정하지는 않습니다. 결과는 다음과 같습니다.

| 파일 | 내용 |
|---|---|
| `02-detail-<방향>.html` · `.png` | 선택한 방향을 실제 화면별로 구체화한 시안 |
| `DECISION.md` | 측정값, 추가 토큰, 인터랙션 선택, 적용 작업 목록 |

### link-skill-authoring

**스킬이 언제 발동하고, 무엇을 추측하지 않으며, 어디까지 책임질지를 정하는 기준입니다.**

모든 스킬에 적용하는 규칙은 두 가지입니다.

1. 필요할 때 발동하고, 아닐 때는 조용히 있어야 합니다.
2. 알 수 없는 것을 추측했다면 그 사실을 숨기지 않아야 합니다.

각 스킬의 계약 한 줄과 검토 질문은 스킬 종류에 맞을 때만 사용합니다. 이 스킬은 작성 기준을
제공하며, 초안·테스트·평가를 맡는 `skill-creator`를 대신하지 않습니다.

[사용법 자세히](plugins/link-skill-authoring/README.md)

### link-skill-packer

**스킬 폴더를 검사한 뒤, 다른 컴퓨터에 복사할 수 있는 ZIP 파일로 묶습니다.** Python이 필요합니다.

GitHub나 플러그인 마켓플레이스를 쓸 수 없는 환경에서 사용합니다. 받는 컴퓨터에서 스킬이 아무 오류
없이 목록에서 사라지는 문제를 보내기 전에 검사하는 것이 핵심입니다.

- 검사를 통과하고 대상 스킬을 확인하기 전에는 ZIP을 만들지 않습니다.
- 스킬 파일을 대신 고치지 않습니다.
- 일부 파일만 골라 담지 않습니다.
- ZIP을 메일·메신저·공유 드라이브로 보내지는 않습니다.

받는 사람은 패커를 설치할 필요가 없습니다. ZIP 안의 `INSTALL.md`를 읽고 스킬 폴더를 복사하면
됩니다. 이미 복사했는데 목록에 뜨지 않는 문제를 진단할 때만 패커를 선택적으로 사용할 수 있습니다.

[사용법 자세히](plugins/link-skill-packer/README.md)

## 설치

### 전부 설치

```bash
claude plugin marketplace add Link-1214/link-skills
claude plugin install link@link-skills
```

`link`는 자체 스킬이 없는 묶음용 플러그인입니다. 나머지 플러그인을 의존성으로 가리킵니다. 새 버전은
다음 명령으로 받습니다.

```bash
claude plugin update link@link-skills
```

### 필요한 플러그인만 설치

마켓플레이스를 먼저 등록한 뒤 필요한 것만 설치합니다.

```bash
claude plugin install link-design-pitch@link-skills
claude plugin install link-skill-authoring@link-skills
claude plugin install link-skill-packer@link-skills
```

### 확인과 제거

```bash
claude plugin list
claude plugin uninstall link-design-pitch
```

오류가 있으면 Claude Code 대화창에서 `/plugin`을 열고 **Errors** 탭을 확인합니다.

기본 설치 범위는 사용자 범위입니다. 팀 저장소에 설정을 함께 커밋하려면 `--scope project`, 현재 작업
폴더에서만 쓰려면 `--scope local`을 붙입니다.

## 다른 에이전트에서 사용

Claude 플러그인 설치는 필요하지 않지만, 모든 AI에서 바로 쓸 수 있다는 뜻은 아닙니다. 다음 조건을
갖춘 로컬 에이전트가 필요합니다.

| 필요한 기능 | 이유 |
|---|---|
| 로컬 파일 읽기 | `SKILL.md`와 참조 문서를 읽어야 함 |
| 프로젝트 파일 쓰기 | 시안과 결정 기록을 남겨야 함 |
| 명령 실행 | 저장소를 받고 패커의 Python 스크립트를 실행할 때 필요 |
| HTML 렌더링과 화면 캡처 | 디자인 스킬의 PNG 산출물을 만들 때 필요 |

저장소를 내려받습니다.

```bash
git clone https://github.com/Link-1214/link-skills.git
```

그다음 필요한 `SKILL.md` 경로를 에이전트에게 알려 줍니다.

```text
디자인 방향을 정해야 해.
<받은경로>/link-skills/plugins/link-design-pitch/skills/link-design-pitch/SKILL.md를
읽고 지침대로 진행해 줘.
```

매번 경로를 적기 번거롭다면 프로젝트의 `AGENTS.md`에 다음처럼 연결합니다.

```markdown
시각 방향이 정해지지 않았다면
<받은경로>/link-skills/plugins/link-design-pitch/skills/link-design-pitch/SKILL.md를 따른다.

방향이 정해졌고 실제 기능과 내용이 만들어졌다면
<받은경로>/link-skills/plugins/link-design-pitch/skills/link-design-pitch-detail/SKILL.md를 따른다.

스킬을 만들거나 고치거나 검토한다면
<받은경로>/link-skills/plugins/link-skill-authoring/skills/link-skill-authoring/SKILL.md를 따른다.

만든 스킬을 Git 없이 남에게 넘겨야 한다면
<받은경로>/link-skills/plugins/link-skill-packer/skills/link-skill-packer/SKILL.md를 따른다.
```

저장소의 [`AGENTS.md`](AGENTS.md)에는 에이전트가 읽을 전체 안내가 있습니다. 갱신하려면 저장소
폴더에서 `git pull`을 실행합니다.

## 설계 원칙

- **규칙과 이유를 함께 적습니다.** 예상하지 못한 상황에서도 에이전트가 이유를 근거로 판단할 수
  있어야 합니다.
- **참조 문서는 필요할 때만 읽습니다.** 항상 읽는 문서는 `SKILL.md` 하나이고, 나머지는 단계에 맞춰
  필요한 부분만 읽습니다.
- **결과를 바꾸는 결정 앞에서 멈춥니다.** 되돌리기 쉬운 사실 확인까지 매번 묻지는 않습니다.
- **특정 에이전트의 전용 도구를 계약으로 삼지 않습니다.** 같은 결과를 만들 수 있다면 환경에 있는
  수단을 사용합니다.
- **실사용에서 확인된 문제를 기준으로 바꿉니다.** 변경 근거는 [`CHANGELOG.md`](CHANGELOG.md)에
  기록합니다.

새 스킬을 이 저장소에 추가하는 방법은 [`AUTHORING.md`](AUTHORING.md)에 있습니다.

## 운영과 언어

개인 작업에 맞춰 만든 도구를 공개한 저장소입니다. 방향성이 뚜렷하므로 작업 방식과 맞지 않을 수
있습니다. 실행 전에 각 플러그인의 README를 읽어 보세요.

릴리스할 때 버전을 직접 올립니다. 버그 수정은 patch, 새 동작은 minor, 호출 이름이나 산출물 형식의
변경은 major로 구분합니다. 이슈와 PR은 환영하지만 답장을 보장하지는 않습니다.

스킬은 외부 서비스로 데이터를 보내지 않습니다. 패커도 ZIP을 지정한 로컬 경로에 만들 뿐 전송하지
않습니다.

사람이 읽는 문서는 한국어입니다. 모델이 읽는 `SKILL.md`와 `references/`는 영어입니다. 대화 응답과
사용자용 문서는 사용자가 쓰는 언어로 작성하도록 지시돼 있습니다. 검사 스크립트의 원시 로그처럼
도구가 직접 출력하는 문구는 영어일 수 있습니다.
