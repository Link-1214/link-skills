# link-skill-authoring

**스킬이 무엇을 보장해야 하는지 정하는 기준입니다.** 스킬 1개.

```bash
claude plugin install link-skill-authoring@link-skills
```

| 호출 | 하는 일 |
|---|---|
| `link-skill-authoring:link-skill-authoring` | 스킬을 만들거나 고치거나 검토할 때 기준을 댑니다 |

**어디에 쓰나.** 스킬을 새로 만들 때, 이미 있는 스킬을 고칠 때, 남이 만든 스킬을 검토할 때.
스킬이 엉뚱할 때 뜨거나 떠야 할 때 안 뜨는 경우에도 씁니다. 그건 `description` 문제라 기준이
다룹니다.

## 이 스킬이 해결하는 것

**기준이 매번 새로 만들어지는 문제.** 스킬을 만들 때마다 무엇을 잘 만든 것으로 볼지 다시 정하면
저장소가 중구난방이 됩니다. 그렇다고 긴 체크리스트를 만들면 이번엔 안 맞는 항목을 억지로 채우게
됩니다. 감사하는 스킬과 시안을 펼치는 스킬은 잘 만든 모습이 다르기 때문입니다.

**그래서 공통 규칙을 둘로 줄였습니다.** 기준은 하나입니다 — **어겼을 때 조용히 실패하는가.**
헷갈리게 쓰였거나 느린 스킬은 쓰다 보면 저절로 드러나므로 규칙이 필요 없습니다. 규칙이 값을 하는
자리는 틀렸는데 아무도 모르는 쪽뿐입니다.

**나머지는 스킬이 스스로 정합니다.** 공통 규칙을 늘리는 대신, 각 스킬이 자기 약속 한 줄을
`SKILL.md` 에 적습니다.

## 무엇이 들어 있나

**규칙 하나. 필요할 때 뜨고, 아닐 때 안 뜬다.**

아무리 잘 쓴 스킬도 발동하지 않으면 없는 것과 같습니다. `description` 이 모델의 유일한 판단
재료라 트리거는 넉넉하게 씁니다. 사용자가 실제로 칠 만한 표현, 증상, 동의어를 넣습니다.

**그런데 절차는 넣지 않습니다.** superpowers 저장소가 이걸 측정해서 The Description Trap 이라고
이름 붙였습니다. `description` 이 작업 순서를 요약하자 모델이 본문을 열지 않고 요약을 따라갔고,
본문에 두 단계로 적힌 리뷰가 한 단계로 실행됐습니다. 요약이 정본을 밀어낸 겁니다.

판별하는 방법은 한 줄입니다. **`description` 만 읽고 「단계를 다 알았으니 본문은 안 열어도
되겠다」고 판단할 수 있으면 잘못 쓴 것입니다.**

**규칙 둘. 모를 때 추측을 숨기지 않는다.**

스킬이 확신 없이 그냥 진행하면 결과는 여전히 그럴듯해 보입니다. 그래서 이게 취향이 아니라 규칙
입니다. 사용자에게는 뭔가 잘못됐다는 신호가 아예 없으니까요.

평균 처리 시간을 구한다고 해봅시다. 조직마다 대기 시간을 포함하는지, 후처리 시간을 넣는지,
전환된 건을 빼는지가 다릅니다. 스킬이 하나를 조용히 골라 계산하면 비전문가는 **틀린 숫자를 확신을
갖고** 받습니다. 되물을 근거조차 없습니다.

추측을 드러내는 데는 한 문장이면 충분합니다. 대개 가정을 출력에 적는 것으로 끝나고, 멈춰서 묻는
것은 그 선택이 결론을 실제로 바꿀 때입니다.

**계약 한 줄.** 각 스킬이 `SKILL.md` 앞부분에 자기 약속을 한 줄 적습니다. 「이 스킬은 X 하지
않는다」 또는 「Y를 보장한다」 형태입니다. 한 번 읽어서 지켰는지 아닌지 판별되기 때문에 검사가
됩니다. 계약을 못 쓰겠다면 그 스킬은 아직 무엇을 하는 물건인지 정해지지 않은 것이고, 그것 자체가
발견입니다.

**질문 다섯.** 만들기 전에 답해 보는 것들입니다. 답을 정해 두지 않았습니다. 유형마다 다르고
「해당 없음」도 답입니다. 다만 답을 못 하는 질문이 하나라도 있으면 그 스킬은 아직 덜 됐습니다.

## 무엇이 나오나

문서나 파일을 만들지 않습니다. 스킬을 만들거나 검토하는 동안 기준으로 쓰이고, 검토라면 어느
규칙에 걸리는지와 계약을 쓸 수 있는지를 짚어 줍니다.

## 하지 않는 것

**만드는 절차를 대신하지 않습니다.** Claude Code에서는 `skill-creator` 가 초안 작성, 테스트
프롬프트, 평가를 맡습니다. 이 스킬은 그 절차가 겨냥할 기준만 댑니다. 둘 다 씁니다.

**이 저장소에 스킬을 추가하는 방법은 다루지 않습니다.** 마켓플레이스 등록, 의존성, 버전 올리기,
`plugin validate` 는 저장소 최상위 [`AUTHORING.md`](../../AUTHORING.md) 에 있습니다. 이 스킬은
어느 저장소에서 스킬을 만들든 통하는 기준이라 범위가 다릅니다.

**스킬을 대신 써 주지 않습니다.** 기준을 대는 것과 문장을 만드는 것은 다른 일입니다.
