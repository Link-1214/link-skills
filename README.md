# link-skills

**AI와 일하면서, 판단은 내가 쥡니다.**

AI로 일하다 "이건 절차로 굳혀두는 게 낫겠다" 싶은 것들을 스킬로 만들어 모은 저장소입니다.

AI는 선택지를 펼치고, 근거를 대고, 실행하는 데 강합니다. 다만 **핸들은 그 일을 아는 사람이
쥐어야 합니다.** AI가 대신 결정해 버리면 두 가지를 잃습니다.

**고르지 않았을 길을 볼 기회.** 답 하나만 받으면 판단이 매번 AI에게 넘어갑니다. 다른 길을 같이
봐야 무엇이 왜 나은지 스스로 따져 볼 수 있고, 그래야 다음 결정이 더 나아집니다.

**왜 이 길로 왔는지 설명할 근거.** 결정한 이유를 모르면 그다음 지시가 흐려집니다. 지시가
흐려지면 프로젝트는 방향을 잃습니다.

그래서 여기 스킬은 전부 같은 성질을 갖습니다. **판단이 필요한 지점에서 멈추고 묻습니다.**
그리고 무엇을 왜 정했는지 파일로 남깁니다.

## 플러그인이 처음이라면

Claude Code를 확장하는 방식입니다. 세 단계로 되어 있습니다.

| | 무엇 | 하는 일 |
|---|---|---|
| **마켓플레이스** | 저장소 | 한 번 등록해 두는 목록. 이 저장소가 그것입니다 |
| **플러그인** | 설치 단위 | 목록에서 골라 설치합니다. 스킬 여러 개를 담습니다 |
| **스킬** | 호출 단위 | 실제로 부르는 것. `link-design-pitch:link-design-pitch` |

설치한 스킬은 대화 중에 이름으로 부르거나, 상황이 맞으면 AI가 알아서 씁니다.

설치는 플러그인 단위입니다. 한 플러그인 안의 스킬은 따로 받을 수 없습니다. 서로 없으면 의미가
없는 스킬은 그래서 한 플러그인으로 묶습니다.

## 스킬 목록

### link-design-pitch

**시각 방향을 고르고, 정해진 뒤 실제 화면에 적용합니다.** 스킬 2개.

```bash
claude plugin install link-design-pitch@link-skills
```

| 순서 | 호출 | 하는 일 |
|---|---|---|
| 1 | `link-design-pitch:link-design-pitch` | 질문 5개 → 시안 10개 → 추천 → **멈추고 선택을 물음** |
| — | *직접 만드는 단계* | 실제 기능과 내용을 만듭니다 |
| 2 | `link-design-pitch:link-design-pitch-detail` | 정해진 방향을 모든 화면에 적용 → 인터랙션 선택지 제시 |

**어디에 쓰나.** 웹·데스크톱 앱, 모바일 앱, 그리고 Word·Excel·PowerPoint 문서까지.

**왜 둘로 나뉘어 있나.** AI와 작업하다 보면 방향을 정한 뒤에 **실제로 만드는 단계**가 옵니다.
전체 테마를 먼저 잡고, 그에 맞춰 기능과 내용을 만들고, 그다음 디자인 통일성을 맞추는 순서입니다.
한 번에 하려고 하면 아직 없는 화면을 AI가 상상해서 그리는데, 목록이 몇 줄인지 제목이 얼마나 긴지는
만들어 봐야 알기 때문에 대부분 다시 그리게 됩니다.

#### 이 스킬이 해결하는 것

**디자인 도메인 지식이 없어도 됩니다.** "글래스모피즘으로 해줘"라고 요청하려면 그 단어를 먼저
알아야 합니다. 용어를 모르면 원하는 걸 설명할 방법 자체가 없습니다. 이 스킬은 29가지 시각 방향을
**당신이 요청한 내용을 기반으로 렌더해서** 보여줍니다. 전문 용어는 몰라도 괜찮습니다. 눈으로
고르세요.

**산출물이 달라도 톤앤매너가 하나로 갑니다.** 발표 자료·대시보드·보고서를 각각 만들면 색과 글꼴과
여백이 제각각이 됩니다. 한 번 정한 방향을 토큰 값까지 기록으로 남겨 두면, 다음에 무엇을 만들든
같은 디자인 시스템 위에서 시작합니다.

#### 무엇이 나오나

프로젝트가 문서를 두는 곳에 만들어집니다. `docs/` 가 있으면 `docs/design/`, 없으면 `design/`.
**해당 폴더가 없으면 새로 만듭니다.**

| 파일 | 내용 |
|---|---|
| `01-directions.html` · `.png` | 시안 10개 보드. HTML은 브라우저용, PNG는 GitHub·메신저처럼 HTML이 안 열리는 곳용 |
| `02-detail-<방향>.html` · `.png` | 선택한 방향을 적용한 모든 화면 |
| `DECISION.md` | 답변·판정·측정값·색상 토큰. 다음 세션과 다른 AI가 읽는 기록 |

[**사용법 자세히 →**](plugins/link-design-pitch/README.md)

## 설치

### 이 저장소의 스킬을 전부 설치

마켓플레이스를 등록하고 `link` 을 설치합니다.

```bash
claude plugin marketplace add Link-1214/link-skills
```

```bash
claude plugin install link@link-skills
```

`link` 은 스킬이 없는 플러그인입니다. 나머지 플러그인을 의존성으로 가리키기만 합니다. 그래서 한 번
설치하면 전부 들어오고, 이 저장소에 새 스킬이 추가되면 아래 명령으로 받을 수 있습니다.

```bash
claude plugin update link@link-skills
```

### 원하는 스킬만 설치

마켓플레이스를 등록한 뒤, 목록에서 필요한 플러그인만 고릅니다.

```bash
claude plugin install link-design-pitch@link-skills
```

### 설치 확인과 제거

```bash
claude plugin list
```

문제가 있으면 `/plugin` 의 Errors 탭에 표시됩니다.

```bash
claude plugin uninstall link-design-pitch
```

### 설치 범위

기본은 사용자 범위라 모든 프로젝트에서 쓸 수 있습니다. 팀 저장소에 함께 커밋하려면
`--scope project`, 내 작업 폴더에만 두려면 `--scope local` 을 붙입니다.

### Codex 등 다른 AI

스킬은 Claude 전용 도구를 하나도 쓰지 않는 평범한 마크다운 문서입니다. **설치할 것이 없습니다.**
저장소를 받아서 경로만 알려주면 됩니다.

```bash
git clone https://github.com/Link-1214/link-skills.git
```

그다음 AI에게 이렇게 말하면 됩니다.

```
디자인 방향을 정해야 해.
<받은경로>/link-skills/plugins/link-design-pitch/skills/link-design-pitch/SKILL.md
읽고 그대로 진행해줘.
```

매번 경로를 적기 번거로우면 프로젝트의 `AGENTS.md` 에 한 번 적어 둡니다.

```markdown
시각 방향이 안 정해졌다면
<받은경로>/link-skills/plugins/link-design-pitch/skills/link-design-pitch/SKILL.md 를 따른다

방향이 정해졌고 실제로 만들어졌다면
<받은경로>/link-skills/plugins/link-design-pitch/skills/link-design-pitch-detail/SKILL.md 를 따른다
```

저장소의 [`AGENTS.md`](AGENTS.md) 에 AI가 읽을 안내가 정리돼 있습니다.
갱신은 받아 둔 폴더에서 `git pull` 하면 됩니다.

## 어떻게 설계했는가

당신이 무엇을 설치하는지 판단하려면 알아야 하는 내용이라 적어 둡니다.

**규칙마다 이유를 함께 적습니다.** 체크리스트나 요약만 적어 두면, 거기 없는 상황을 만났을 때
AI가 멈추거나 엉뚱하게 처리합니다. 왜 그래야 하는지를 알면 예상 못 한 경우도 판단할 수 있습니다.
유난히 구체적인 규칙이 있다면, 그건 그게 없어서 실제로 뭔가 잘못됐던 흔적입니다.

**참조 문서는 필요할 때만 읽습니다.** 항상 읽는 건 `SKILL.md` 하나입니다. 분량이 있는 문서는
앞에 색인을 두어, 전부가 아니라 그때 필요한 부분만 읽습니다. 이것만으로 한 번 실행에 드는
**토큰이 29% 줄었습니다.**

**결정할 것이 나오면 멈추고 물어봅니다.** 예를 들어 시안 10개를 보여준 다음, 어느 것으로 갈지
묻지 않고 곧장 상세 화면까지 만들어 버린다고 해 봅시다. 당신이 다른 걸 골랐다면 그 작업은 통째로
버려집니다. 그리고 더 중요하게는, 고르는 일을 AI가 대신해 버린 셈이 됩니다.

**특정 AI 전용 기능에 기대지 않습니다.** 그 AI에 더 나은 수단이 있으면 쓰고, 없으면 없는 대로
동작합니다. Codex 같은 다른 AI가 설치 없이 그냥 받아서 쓸 수 있는 이유입니다.

**바꾸는 이유는 실사용에서만 나옵니다.** 실제 작업에서 스킬이 깨졌을 때만 고칩니다.
좋아 보여서 미리 넣어 둔 기능은 없습니다.

새 스킬을 만드는 방법은 [`AUTHORING.md`](AUTHORING.md) 에 있습니다.

## 운영 방식

**개인 도구를 공개한 것입니다.** 제가 하는 일에 맞춰 만들었습니다. 그래서 의견이 뚜렷하고, 같은
이유로 안 맞을 수도 있습니다. 돌리기 전에 읽어 보시길 권합니다.

**버전은 직접 올립니다.** 릴리스할 때만 바뀝니다. 고침은 patch, 새 동작은 minor, 호출 이름이나
산출물 형식이 바뀌면 major 입니다. [`CHANGELOG.md`](CHANGELOG.md)

**이슈와 PR은 환영합니다. 다만 답장을 약속하지는 못합니다.** 무엇을 돌렸고 무엇이 일어났는지 적힌
버그 제보는 특히 도움이 됩니다. 기능 요청은 제가 그 필요를 직접 겪지 않으면 만들지 않을 가능성이
큽니다. 포크는 자유롭게 하셔도 됩니다.

**외부로 아무것도 보내지 않습니다.** 스킬은 지시문일 뿐입니다. 외부 서비스를 호출하지 않고,
수집하지 않고, 전송하지 않습니다.

## 문서 언어

사람이 읽는 문서는 한국어입니다.

`SKILL.md` 와 `references/` 는 영어입니다. 그 파일을 읽는 건 사람이 아니라 AI 모델이고, 같은
내용이라도 영어일 때 토큰을 덜 쓰기 때문입니다. **출력은 영어로 나오지 않습니다.** 스킬 안에
"사용자가 쓰는 언어로 답하라"가 들어 있어서, 한국어로 물으면 한국어로 답합니다.
