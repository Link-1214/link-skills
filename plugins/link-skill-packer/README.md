# link-skill-packer

깃허브를 쓸 수 없는 곳에서, 직접 만든 스킬을 옆자리 동료에게 넘기기 위한 스킬입니다.

```
/plugin marketplace add Link-1214/link-skills
/plugin install link-skill-packer@link-skills
```

## 무엇을 하는지

스킬 폴더 하나를 zip으로 묶습니다. 받는 사람은 폴더 하나를 복사하면 설치가 끝납니다.

묶기 전에 검사를 겁니다. **이 스킬의 값어치는 압축이 아니라 그 검사에 있습니다.**

## 어디에 쓰나

원래 스킬은 깃 저장소에 올려 플러그인으로 배포합니다. 회사에서 깃허브가 막혀 있으면 그 길이
통째로 사라지고, 바로 옆자리 사람에게도 스킬을 못 줍니다. 공유 드라이브든 메일이든 메신저든,
파일 하나만 건네줄 수 있으면 이 스킬로 넘길 수 있습니다.

**받는 쪽에서도 씁니다.** 「깔았는데 목록에 안 떠」일 때 원인을 찾아 줍니다. 그때는 포장하지 않고
검사만 하고 멈춥니다. 아무도 배달을 부탁한 적이 없으니까요.

원인은 대개 셋인데, 파일에 흔적이 남는 건 하나뿐입니다.

| 원인 | 어떻게 확인하나 |
|---|---|
| BOM이 붙었거나 frontmatter가 깨졌다 | `check`가 잡습니다 |
| 깐 세션에서 바로 확인했다 | 스킬 목록은 세션 시작 때 한 번 읽힙니다. 새 세션에서 보면 있습니다 |
| 폴더가 한 겹 깊다 | `SKILL.md` 가 `skills\<이름>\` 바로 아래 있는지 봅니다 |

세 번째는 흔합니다. 압축을 풀면 zip 이름을 딴 폴더가 하나 더 생기는데, 그 바깥 것을 복사하면
이렇게 됩니다.

스킬이 **뜨긴 뜨는데 엉뚱한 때 뜨는** 거라면 이 스킬이 아닙니다. 그건 설명문 문제라
[`link-skill-authoring`](../link-skill-authoring/README.md) 쪽입니다.

## 이 스킬이 해결하는 것

**스킬은 조용히 고장 납니다.** 에러가 안 납니다. 그냥 목록에 없습니다. 받은 사람은 「안 되는데요」
말고 할 말이 없고, 준 사람은 어디를 봐야 할지 모릅니다. 그런데 같은 문제를 보내기 전에 보면 몇
초면 잡힙니다.

막는 항목은 전부 그 부류입니다.

| 막는 것 | 이러면 |
|---|---|
| `SKILL.md` 가 없다 | 스킬 폴더가 아닙니다 |
| `SKILL.md` 맨 앞에 BOM | 설정이 통째로 무시돼 목록에 안 뜹니다 |
| frontmatter 블록이 없다 | 위와 같습니다 |
| `description` 이 없다 | 모델이 부를 근거가 없어 안 뜹니다 |
| `description` 안에 콜론+공백 (따옴표 없이) | YAML이 다른 뜻으로 읽고 설정을 버립니다 |

다섯 가지뿐입니다. 파일만 열어 보면 참인지 거짓인지 바로 나오는 것들이라 막아도 안전합니다.

이 다섯으로 좁힌 이유가 있습니다. 이 컴퓨터에 깔린 스킬 81개를 패커로 검사해 봤더니, 기준이 조금만
넓어도 **정상인 스킬 13개가 걸렸습니다.**

### 이런 경고가 떠도 대개 정상입니다

패커는 아래 둘을 막지 않고 알려만 줍니다. 걸렸다고 해서 스킬이 고장 난 것이 아닙니다.

- **`name` 이 폴더 이름과 다르다** — 스킬은 문제없이 뜹니다. 호출할 때 쓰는 이름이 폴더 이름이기
  때문입니다. 그런 스킬 5개가 이 컴퓨터에서 지금도 쓰이고 있습니다.
- **참조한 파일이 폴더에 없다** — 스킬 설명서는 자기가 담은 파일뿐 아니라 사용자 프로젝트의
  파일도 자주 언급합니다. 그래서 없는 것이 정상인 경우가 많습니다.

### 패커가 막지 않고 보여만 주는 것

절대경로, 폴더 밖을 가리키는 링크, 비밀번호처럼 보이는 문자열, 사설 IP, 이메일 주소. 그리고 한
문서 안에서 어떤 경로는 풀리는데 어떤 것은 안 풀리는 경우입니다.

문서에 적어 둔 예시일 수도 있고 진짜일 수도 있는데, 그 둘은 기계가 못 가립니다. 그래서 패커는
무엇이 애매한지를 같이 냅니다 — 「절대경로 발견」이 아니라 「예시입니까, 스킬이 실제로 여는
경로입니까」라고.

### 패커가 참고 사항으로만 알려 주는 것

함께 담기는 실행 스크립트, 외부 의존성, `name` 불일치, 그리고 한 문서의 경로가 **전부** 안 풀리는
경우입니다.

가르는 기준은 하나입니다. **그것을 보고 사용자의 답이 달라질 수 있는가.**

`name` 이 달라도 패커는 어차피 폴더 이름으로 싸기 때문에, 사용자가 뭐라고 답하든 같은 zip이
나옵니다. 경로가 전부 안 풀리는 문서는 사용자 프로젝트를 설명하는 문서였습니다 — 이 컴퓨터의 스킬
81개를 검사했을 때 그런 문서가 22건 나왔고, 22건 모두 그랬습니다.

사용자의 답을 바꿀 수 없는 것을 확인 화면에 채워 넣으면, 정작 봐야 할 줄을 놓치게 됩니다.

**패커가 대신 고쳐 주지는 않습니다.** 보내는 길에 남의 스킬에 손대면, 만든 사람이 시험한 것과
받는 사람이 받는 것이 달라집니다.

## 단계별로 어떻게 도는지

두 단계입니다.

**1. 어떤 스킬을 쌀지 확인합니다.** 폴더를 찾아 검사를 돌리고, 이름과 함께 눈에 걸리는 것을
보여준 뒤 한 번 묻습니다. 여기서는 아무것도 만들지 않습니다.

```
Packing `고객관리` — 12 files, 84 KB.
실적_2026Q2.xlsx 는 스킬 파일이 아니라 데이터 파일입니다.
진행할까요?
```

**2. 답을 받으면 zip을 씁니다.** 뺄 파일이 있었으면 폴더에서 지우고 1번부터 다시 합니다.

멈추는 자리는 여기 하나뿐이고, 묻는 것도 하나입니다 — **이 스킬 맞습니까.** 판단할 목록을 따로
내밀지 않습니다. 포장은 정답이 있는 일이고 그 정답은 스크립트가 찾으니까요. 기계가 진짜로 모르는
건 「이 파일이 나가도 되나」 하나인데, 대상 이름을 내용과 같이 부르면 그 자리에서 드러납니다.

### 파일 목록을 다 늘어놓지 않습니다

열네 줄을 보여줘도 아무도 안 읽고, 읽어도 `references/guide.md` 가 위험한지는 이름만 봐선
모릅니다. 판단을 사람에게 떠넘긴 셈이죠. 평범한 것은 개수만 세고, **튀는 것만 이유를 붙여** 냅니다.

```
6 of these look like ordinary skill material — assets/ 1, folder root 2, references/ 2, scripts/ 1

These do not, and placing them is the part no scan can do:
  references/고객명단.md      16 B   nothing in the skill links to it
  실적_2026Q2.xlsx           16 B   a data file rather than skill material
  작업중/메모.txt              20 B   the name reads like a draft or a personal copy
```

튀는 기준은 넷입니다.

- 데이터 파일 (`.xlsx`, `.csv`, `.zip`, `.pdf` 등)
- 초안·임시·사본처럼 읽히는 이름
- 스킬치고 큰 파일
- **`references/` 안에 있는데 아무도 링크하지 않는 마크다운**

마지막 것이 제일 잘 잡습니다. `references/` 아래 마크다운은 `SKILL.md` 에서 찾아가라고 두는
자리입니다. 그러니 아무도 안 가리키는 마크다운은 실수로 흘러든 파일일 가능성이 높습니다.

**패커는 파일이 어디 놓였는지는 보지 않습니다.** 「최상위에 떠 있다」와 「스킬 구조에 없는
폴더다」로 걸러 보기도 했는데, 이 컴퓨터의 스킬 81개를 검사해 보니 걸린 137건 중 136건이 그 둘
때문이었습니다. 한 스킬에서만 49건이 나왔습니다. 그 두 기준은 「이 파일이 나가면 안 된다」가 아니라
「이 사람이 흔한 폴더 구조를 안 썼다」를 재고 있었던 겁니다. 빼고 나니 81개 전체에서 1건으로
줄었고, 시험용으로 심어 둔 위험 파일 4개는 그대로 잡힙니다.

**대개는 보여줄 것도 없습니다.** 스킬 81개를 검사해 보니 72개는 이름과 파일 개수만 나왔습니다.
패커가 없는 것을 억지로 채워 넣지 않기 때문입니다. 전체 목록을 보고 싶으면 `--all` 을 붙이면
됩니다.

## 무엇이 나오나

```
<스킬이름>-skill.zip
├── INSTALL.md          무엇인지, 어떻게 설치하는지, 무엇이 담겼는지
└── <스킬이름>/          이 폴더를 통째로 복사하면 설치 끝
```

`INSTALL.md` 에는 **받는 사람이 알아낼 수 없는 것**이 적힙니다.

- **먼저 깔려 있어야 하는 것.** 담긴 스크립트가 요구하는 실행기(파이썬, PowerShell, bash,
  Node.js)를 적고, `.py` 는 import까지 읽어 표준 라이브러리가 아닌 이름을 남깁니다. `pandas` 를
  쓰는 스킬은 파일이 다 들어 있어도 그게 없는 컴퓨터에서는 죽습니다. zip에 못 담는 것이라 이름이라도
  적어 두는 겁니다. 다만 import는 파이썬만 읽습니다 — `.js` 는 Node가 필요하다고만 적히고 npm
  패키지까지는 못 봅니다
- **담긴 파일 목록과 파일별 SHA-256.** 「복사하세요, 다시 쓰지 마세요」를 **확인할 수 있게**
  만듭니다. 받는 쪽에서 `SKILL.md` 를 다시 저장하면 값이 달라지고 그게 그 자리에서 보입니다.
  며칠 뒤에 「스킬이 안 뜨는데요」로 알게 되지 않습니다
- **설치 방법과 확인 방법**

그리고 **조용히 실패하는 세 가지**를 적어 둡니다. 셋 다 에러가 안 나서, 미리 말해 주지 않으면
「안 되는데요」라는 말만 돌아옵니다.

- **읽어서 새로 쓰지 말고 복사할 것.** 다시 저장하면 BOM이 붙어, 앞서 막아 둔 고장이 마지막
  단계에서 되살아납니다
- **깐 세션에서는 안 보인다는 것.** 스킬 목록은 세션이 시작될 때 읽힙니다
- **복사할 폴더를 헷갈리지 말 것.** 압축을 풀면 zip 이름을 딴 폴더가 하나 더 생깁니다. 복사할
  것은 그 안쪽이고, 바깥 것을 복사하면 경로가 한 겹 깊어져 안 뜹니다

받는 쪽에는 이 스킬이 필요 없습니다. `INSTALL.md` 는 그걸 전제로 씁니다.

내용은 복사 목록입니다. 받는 사람의 에이전트에게 무언가를 실행시키는 지시는 넣지 않습니다.
첨부 파일이 남의 에이전트를 조종하는 모양은, 보내는 사람을 믿더라도 만들지 않는 편이 맞습니다.

## 하지 않는 것

스킬을 만들거나 고치지 않습니다. 무엇을 보장하는 스킬을 만들 것인가는
[`link-skill-authoring`](../link-skill-authoring/README.md) 이 다룹니다.

**폴더에서 일부만 골라 담지 않습니다.** 제외 옵션이 없습니다. 그런 기능이 있다면 주는 사람과 받는
사람이 서로 다른 것을 갖게 되고, 결국 다른 스킬이 됩니다. 파일이나 설정 등을 제외해야 한다면
폴더에서 지우고 다시 돌리세요.

패커는 싸는 쪽 컴퓨터에 아무것도 설치하지 않습니다. zip을 어디로 보내지도 않습니다. 알려 준 자리에
파일 하나 쓰고 끝냅니다.

스킬이 잘 만들어졌는지는 판단하지 않습니다. **옮기는 동안 깨지지 않는지만 봅니다.**

## 필요한 것

파이썬. 표준 라이브러리만 씁니다.
